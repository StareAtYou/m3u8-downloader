# 自动重试、任务表单与预计剩余时间设计

## 意图

让桌面端在无人值守时能从短暂下载故障中自行恢复，并把新建任务所需的全局参数集中到设置页，同时补齐任务列表已有但尚未实现的“预计剩余”信息。

## 目标

- 一个任务首次执行失败后，后台最多再自动执行 3 次；初次执行不计入这 3 次。
- 自动重试次数和下一次重试时间写入 SQLite，后台服务或桌面 App 重启后仍然有效。
- 自动重试采用 2 秒、5 秒、10 秒三级退避，避免持续快速请求故障源。
- 手动点击“重试”会清除旧错误、取消待执行的自动重试，并重新获得 3 次自动重试额度。
- 任务名称输入框首次显示为空，使用占位提示，与 M3U8 地址输入框一致。
- 顶部添加任务区域不再显示“保存到”输入框或“允许覆盖已存在文件”复选框。
- 默认保存目录和允许覆盖策略都由设置页管理、写入现有 `settings.json`，并用于单任务和批量任务。
- 下载过程中根据片段完成速率显示预计剩余时间；没有可靠估值时显示 `—`。

## 非目标

- 不改变 CLI 的 `--save-dir` 和 `--overwrite` 参数；CLI 显式参数继续优先。
- 不对取消、暂停、服务中断或用户主动停止的任务执行自动重试。
- 不保证 ETA 是媒体播放时长；它表示按当前实际下载进度估算的完成下载所需墙钟时间。
- 不引入可配置的重试次数或退避时间，当前固定为 3 次和 2/5/10 秒。
- 不重做任务列表布局，只接通现有“预计剩余”列。

## 约束与行为

### 自动重试

任务表新增 `auto_retry_count INTEGER NOT NULL DEFAULT 0` 和可空的 `next_retry_at TEXT`，数据库 schema 从 v1 迁移到 v2。已有任务迁移后次数为 0，不丢失任何现有字段。

工作进程失败后仍先发出 `FAILED` 事件。管理器保存公开错误；若 `auto_retry_count < 3`，则增加次数并写入下一次 UTC 重试时间。服务现有监控循环会在时间到达后将任务由 `FAILED` 转回 `QUEUED`，再交给正常的 FIFO 调度器。等待期间公开快照保留失败原因、当前重试次数和下一次重试时间，桌面端状态显示为“等待重试 1/3”等文案。

所有非用户主动导致的工作进程失败都使用同一重试额度，包括探测、解析、分片下载、合并及进程异常退出。`FileExistsError` 是需要用户修改设置或名称的确定性冲突，不自动重试；任务直接保持最终失败。取消、暂停和中断不是失败，不进入自动重试。

当第 3 次自动重试仍失败时，任务保持 `FAILED`，清除 `next_retry_at`，界面恢复普通失败状态和手动重试按钮。成功完成时保留 `auto_retry_count` 作为本次任务历史，但不再安排重试。用户手动重试会把次数重置为 0，因此新的手动周期仍有 3 次自动机会。

### 新建任务参数

`AppSettings` 新增严格布尔字段 `overwrite_existing`，默认 `false`，沿用 JSON 设置存储的原子写入与重启恢复机制。旧设置文件没有该键时使用默认值，无需单独文件迁移。

桌面桥接层持有 `defaultSaveDir` 和新的 `overwriteExisting` 属性。设置加载或保存成功时同步这两个属性。QML 的单任务提交改为只传 URL 和任务名称，桥接层在提交瞬间加入当前保存目录与覆盖策略；批量任务同样统一加入这两个值。这样顶部表单和批量对话框不再各自保存重复配置。后台协议和 CLI 的显式 `save_root`、`overwrite` 结构保持兼容。

如果设置文件中的默认保存目录为空，桌面桥接层继续使用用户 `Downloads` 目录作为运行时默认值；设置页会显示实际使用值，保存后写入文件。

顶部表单在宽屏和紧凑布局下只包含 URL、任务名称、添加任务、批量添加和输出文件预览。任务名称改为 `text: ""` 与示例 `placeholderText`；提交成功后仍清空 URL 和任务名称，失败时仍保留。

现有“文件已存在”确认弹窗继续保留，作为单任务的一次性覆盖授权：当全局 `overwrite_existing=false` 且提交阶段发现冲突时，用户可以只对当前任务确认覆盖，不修改全局设置。提交阶段的冲突仍不会创建任务记录；如果提交后才因竞争在工作进程中出现 `FileExistsError`，则保留失败记录且不自动重试。

### 预计剩余时间

工作进程在每个片段完成时，根据 `elapsed / completed * (total - completed)` 计算 `eta_seconds`。值采用单调时钟产生，写入工作事件、SQLite 和公开任务快照；数据库字段为可空 REAL。尚无已完成片段、非下载状态或数据无效时不提供估值。

桌面任务模型新增 `etaText` 展示角色：

- 小于 60 秒：`约 N 秒`
- 60 分钟以内：`约 N 分钟`
- 1 小时及以上：`约 H 小时 M 分钟`，整小时时省略分钟
- 不可靠或非下载状态：`—`

现有任务表“预计剩余”列绑定 `etaText`。暂停、排队、探测、解析、等待合并、合并、完成和失败时均显示 `—`，避免把旧估值误认为当前预测。

## 数据与兼容性

- SQLite v1 → v2 仅通过 `ALTER TABLE` 增加三列：`auto_retry_count`、`next_retry_at`、`eta_seconds`。
- `TaskRecord`、`TaskSnapshot` 和序列化结果增加对应字段；旧数据库会获得安全默认值。
- JSON 设置增加 `overwrite_existing`；读取旧 JSON 时允许缺失该字段并补默认值，但未知字段和类型错误仍然报错。
- 服务协议动作名称不变，现有终端客户端不需要升级才能继续提交任务。

## 错误与边界处理

- 待重试任务可以被删除或手动重试；删除记录会同时取消其持久化重试计划。
- 待重试期间不会占用并发下载槽。
- 多个任务同时到期时仍按任务原始创建时间 FIFO 调度。
- “全部开始”只恢复暂停任务，不提前触发仍处于 2/5/10 秒退避期的失败任务。
- 服务关闭时不创建额外计时线程；重启后监控循环按持久化时间恢复。
- 系统时间变化可能令一次持久化退避提前或延后；它只影响下一次尝试的等待时间，不影响次数上限。
- ETA 只接受有限且非负的数值；非法事件数据按未知值处理，不进入 QML。

## 测试策略

- 存储迁移测试验证 v1 数据无损升级、重试字段和 ETA 字段默认值。
- 管理器测试使用可控时钟验证 2/5/10 秒退避、最多 3 次、FIFO、手动重置、确定性文件冲突不重试及重启恢复。
- 工作进程测试验证进度事件产生合理 ETA，首个片段前不伪造 ETA。
- 设置测试验证覆盖策略持久化、旧 JSON 缺键兼容和非布尔值拒绝。
- GUI 模型与 QML 测试验证 `etaText`、空任务名称占位、顶部字段移除、设置页覆盖选项以及单任务/批量提交载荷。
- 最终运行完整 pytest、Ruff 检查和格式检查。

## 考虑过的方案

### A. 后台管理器持久化重试（选定）

重试生命周期由服务统一管理，GUI 关闭或服务重启后仍可恢复；能复用当前任务状态机和 FIFO 调度。代价是需要一次 SQLite schema 迁移，并扩展公开快照。

### B. 工作进程内部循环重试

改动集中，但进程崩溃或服务重启会丢失重试次数，任务状态也无法准确表达等待重试，因此不采用。

### C. 桌面界面观察失败后发起重试

实现直观，但界面关闭后失效，而且终端和 GUI 会产生不一致行为，因此不采用。

## 验收标准

- 可重试故障连续发生时总执行次数最多为 4（初次执行 + 3 次自动重试）。
- 关闭并重启服务不会重置次数或丢失下一次重试计划。
- 顶部添加区域没有保存目录和覆盖复选框；设置页保存后，新建的单任务与批量任务都使用该配置。
- App 初次打开时任务名称输入框为空并显示占位提示。
- 下载任务在获得至少一个片段进度后显示非 `—` 的预计剩余时间，离开下载状态后恢复 `—`。
- 原有 CLI、任务删除、暂停恢复、多任务合并和设置持久化测试继续通过。
